# 1.4.0 / V28 검증 범위

기록일: 2026-11-06. 로컬 GitHub 배포 준비본 기준입니다. 실제 업로드·Pages 배포 결과와 구분합니다.

## 게임 코드 변경

TV 라이브의 원 상품 추첨을 신급라이브 전에 한 번 준비하고 완료를 기다립니다. 원래 첫 상점 상품·24개 후보·다섯 연출 후보를 보존하며, 노트 UI가 준비된 뒤 원 후보 순서로 아이템 이미지를 연결합니다. 별도 고등급 재추첨이나 새 당첨 추첨은 하지 않습니다.

V28은 시험판의 쥬리 100% 강제 두 바이트를 원래 조건 분기로 복구합니다. 원래 상품 연동 등장 판정과 보장 조건을 사용하며, 등장하지 않아도 첫 상점 상품과 후보들은 유지합니다. 기본 Print → 추가구매·코인 → 추가 Shop → 선택 CharaMake → 추가 Print → End는 유지합니다.

실제 공급표를 원 코드로 읽는 확률·최종 분기 45조건, 보장 분기 12조건, God 결과부터 Shop으로 이어지는 6조건을 통과했습니다. 기존 V27 체인 129조건·후보 보존 69조건·UI 연결 42조건은 해당 코드의 바이트 동일성으로 인계했습니다. 과거 강제 100% 검사 결과는 인계하지 않았습니다. 일부 자원·할당·장치 경계는 통제된 자료를 사용했습니다.

공개 목표에서는 실패한 V21 흰색 전환 시험 후크와 본문만 제외했습니다. 이 범위와 PE 체크섬 외에는 설치용 V28과 전 바이트가 같습니다. 따라서 두 목표의 전체 SHA는 다릅니다. 기존 QR·카메라·밝기·CharaMake 기능은 보존합니다.

## 개인 설정이 없는 실행

Node 24.22.1에서 빈 HOME·사용자 설정 폴더와 운영체제 필수 변수만 있는 환경을 사용했습니다. Node의 파일 권한으로 준비본·명시한 원본만 읽을 수 있게 제한하고, 허용하지 않은 파일 읽기가 거부되는 것을 확인했습니다. 개인 키·토큰 환경변수는 전달하지 않았습니다.

실행한 공개 명령은 다음과 같습니다. 파일 읽기·쓰기 허용 인자는 준비본과 임시 빈 프로필만 가리켰습니다.

```text
node --permission <읽기·쓰기 허용 인자> scripts/verify-site.mjs --write
node --permission <읽기·쓰기 허용 인자> scripts/verify-site.mjs
node --permission <읽기·쓰기 허용 인자> --test --test-isolation=none tests/*.test.mjs
node --permission <읽기·쓰기·원본 RAR 허용 인자> tests/real-archive.mjs <original.rar>
```

- 기본 엔진·manifest 로드와 가상카메라 기본 선택: 통과.
- 두 지원 원본 EXE에 각각 차분 적용: 공개 목표 EXE와 전체 바이트·SHA 일치.
- 정적 자산·WASM·동일 사이트 경로·개인정보 형식 검사와 40개 테스트: 모두 통과.
- 실제 원본 RAR → 선택 파일 SHA 확인 → 패치 → 결과 ZIP 생성: 통과.
- 약 9.83 GB RAR에서 5,579,032바이트만 읽었습니다. 대상 여섯 파일을 검증하고 변경 다섯 파일을 출력했으며 업로드는 0바이트입니다. 설정만 변경하는 경로도 통과했습니다.

RAR 실행 검사는 브라우저와 같은 JavaScript 패치 모듈·RAR WASM을 Node에서 사용했습니다. 실제 브라우저 화면·다운로드 UI 테스트와 게임 실행을 대신하는 증거는 아닙니다.

## 키·공개 자료와 한계

패처 엔진은 자체 암호화 키나 개인 환경 설정 없이 실행합니다. 게임 QR 기능은 사용자가 제공하는 원본 `QRReader.dll`을 사용하며, 패처는 DLL의 SHA-256·크기만 검증합니다. 원본 DLL·제한된 공유 프로토콜 키·완성 EXE는 소스 ZIP과 사이트에 포함하지 않습니다.

소스·압축을 푼 차분·추가된 native 코드·소스 ZIP은 일반적인 개인정보 형식과 알려진 비공개 표본에 대해 별도로 검사합니다. 개인 값이나 실제 키를 공개 검사 목록·테스트에 넣지 않습니다. 이 검사는 모든 미지 식별자와 비밀의 부재를 보장하지 않습니다.

V28 실제 플레이·화면·노트 아이템 이미지·코인 입력·인쇄는 사용자 확인 전입니다. 이전 마이티켓 출력·로그인과 V19 드림 진행의 사용자 확인을 V28 성공으로 확대하지 않습니다. V17 우정티켓 인식과 밝기 변경 뒤 새 드림 출력 확인도 남아 있습니다.

이번 준비에서는 원격 GitHub 업로드·Pages·릴리즈·공개 CI 로그를 검증하지 않았습니다. 로컬 이력 검사와 현재 준비본 검사는 공개 커밋 검증을 대신하지 않습니다. 업로드 후 실제 공개 커밋·릴리즈 해시를 다시 확인해야 하며, 외부 캐시·포크·다른 사람의 복제본은 이 범위 밖입니다.
